# KOVA Store 講師用資料

この資料は研修担当者向けです。店舗画面には脆弱性の説明や進行手順を載せていません。アプリは架空の顧客・商品・注文のみを扱い、サーバーから外部サービスへの通信や実決済は行いません。演習は自分で起動したこのインスタンスに限定してください。

## 対象範囲

KOVA Store は一般的な EC サイトに見えるよう、商品検索、レビュー、アカウント、カート、送料見積り、注文を備えています。ログインや CSRF 確認などはある程度実装されていますが、下表の業務処理には意図的な欠陥を残しています。「ログインしている」「画面上に入力欄がない」「見積り API を呼んだ」という事実だけでは、各処理の安全性は保証されないことを観察します。

| 観察する欠陥 | OWASP Top 10:2025 との対応 | 実際に起こること | 修正時の要点 |
| --- | --- | --- | --- |
| 注文の BOLA / IDOR | A01 Broken Access Control | 他の架空顧客の注文を、注文番号を指定して閲覧できる | 注文ごとにログイン者との所有関係をサーバーで確認する |
| プロフィールの権限フィールド一括更新 | A01 Broken Access Control、API Top 10:2023 API3 | 購入者が本来更新できない `role` を送信できる | 許可フィールドだけを明示的に更新し、権限変更を管理操作に分離する |
| 商品検索の SQL インジェクション | A05 Injection | 検索条件を変え、非公開商品の架空カナリアが結果に現れる | 検索条件をプレースホルダーに束縛し、公開範囲を常に強制する |
| レビューの保存型 XSS | A05 Injection | 投稿本文が商品画面で HTML として解釈される | レビューをテキストとして描画し、必要な書式だけを安全に許可する |
| 送料のクライアント側金額改ざん | A06 Insecure Design | 見積り結果を変えた注文をサーバーが受け入れ、合計額が下がる | サーバーが配送方法・宛先から送料を再計算して注文を確定する |

分類は [OWASP Top 10:2025](https://top10.owasp.org/2025/0x00_2025-Introduction/) と [OWASP API Security Top 10:2023 API3](https://api-security.owasp.org/editions/2023/en/0xa3-broken-object-property-level-authorization/) を参照しています。これは Top 10 の全10カテゴリを実装した教材ではありません。A02 Security Misconfiguration、A03 Software Supply Chain Failures、A04 Cryptographic Failures、A07 Authentication Failures、A08 Software or Data Integrity Failures、A09 Security Logging and Alerting Failures、A10 Mishandling of Exceptional Conditions を意図的な欠陥として追加していません。依存パッケージを故意に古くしたり、外部URLへアクセスする実SSRF、実決済を組み込んだりもしません。

既にある防御も観察対象です。パスワードはソルト付きハッシュで保存し、ログイン時にセッションを更新します。Cookie は `HttpOnly` と `SameSite=Lax`、状態を変えるAPIには CSRF トークン確認があります。カートの数量、在庫、商品の価格はサーバー側で確認し、多くのデータベース処理では値を束縛しています。これらの防御は有効ですが、別の API の所有者確認・更新可能フィールド・送料再計算を代わりに行うものではありません。XSS では `HttpOnly` によりCookie値を直接読むことは抑えられても、ページ上で実行されるコード自体は防げません。

SQL インジェクションの文字列連結は商品だけの使い捨てメモリ SQLite に限り、顧客・注文・セッションの表には接続しません。それでも結果のIDを通じて非公開の商品情報が漏れるため、実際の影響を確認できます。レビュー、注文、権限の欠陥は架空データを保存する通常の業務処理にあり、演習後は初期化が必要です。

## 準備

[README](../README.md) の手順で `docker compose up --build -d --wait` します。Mac からは `http://127.0.0.1:4327`、VMware NAT の Kali からは追加 Compose ファイルを使い、この環境では `http://192.168.180.1:4327` です。複数人で同じインスタンスを使うとレビューや注文が共有されます。演習の再現性が必要なら受講者ごとにインスタンスを分けてください。

初期の架空顧客は次の2人です。

| 顧客 | メール | パスワード | 初期注文 |
| --- | --- | --- | --- |
| 美緒 | `mio@kova.local` | `KovaDemo2026!` | `K-2026-1001` |
| 陽 | `haru@kova.local` | `KovaDemo2026!` | `K-2026-1002` |

画面操作の後で観察に使う場合は、ブラウザーの開発者ツールの Network タブで自分のリクエストを確認します。API に直接アクセスするときは、同じブラウザーのログイン済みセッションと CSRF トークンを使います。カナリアや注文の中身はすべて演習用の架空データです。

## 観察例

### 1. 注文の所有者チェック

美緒でログインし、本人の注文 `K-2026-1001` を確認します。次に同じセッションのまま `GET /api/orders/K-2026-1002` を開きます。陽の注文が返る場合、認証は通っていても注文単位の認可が欠けています。修正するときは、IDの形式や推測しやすさに頼らず、取得クエリと返却前の両方で所有者を確認します。

### 2. 非公開商品の検索

通常の検索では公開商品だけが出ます。検索欄に `%') OR 1=1 -- ` を入力し、結果を確認します。非公開の「STUDIO 試作モデル」（社内限定）が一覧に現れ、検索 API の JSON では `description` に `CANARY-KOVA-PRODUCT-7` が含まれます。検索語が SQL の条件式として解釈されていることを確かめ、公開判定も含めて値を SQL 文字列に直接連結しない修正を考えます。

### 3. レビューの保存と再表示

商品ページから、無害な表示変更だけを行う HTML をレビュー本文として投稿します。例: `<img src=x onerror="document.title='KOVA REVIEW XSS'">`。保存後に商品ページを再表示し、ブラウザーのタイトルが変わるかを観察します。送信時の値が別の閲覧者の画面でもコードとして実行される点が保存型 XSS の影響です。実際の秘密情報の取得や外部送信は演習に不要です。

### 4. プロフィール更新とロール

通常のプロフィール画面では名前の変更だけを行い、Network タブで `PATCH /api/profile` を確認します。同じエンドポイントへ `{"role":"staff"}` を含む JSON を送信し、`GET /api/staff/overview` が使えるようになるかを確認します。入力欄がないフィールドでも HTTP クライアントから送れるため、サーバー側で更新対象を限定する必要があります。

### 5. 送料見積りと注文確定

`POST /api/shipping/quote` に `{"method":"standard","postalCode":"100-0001"}` を送ると通常の送料は480円です。Network タブで注文確定の `POST /api/checkout` を確認し、同じ商品の注文で `shippingFee` を `0` に変えた場合の合計額を比べます。改ざんした送料は注文に保存され、合計額とスタッフ向け売上にも反映されます。送料の見積りを先に呼んだことは、注文確定時の金額を信頼する根拠にはなりません。サーバーが配送条件をもとに再計算し、クライアント送信額は参照しない設計にします。

## 観察後の整理

各演習で、入口の HTTP リクエスト、欠けたサーバー側の確認、返却または保存された結果を並べて記録します。その後、入力検証・認証・認可・出力処理・業務ルールを区別して、どの層で防ぐべきかを議論します。特に「CSRF があるからロール更新も安全」「画面に非公開商品がないから検索結果にもない」といった推論を、実際のリクエストと照らします。

サイト内には進捗や正解表示を組み込んでいません。受講者が操作と観察を記録する形式を想定しています。

## リセット

インスタンス内の注文、レビュー、プロフィール変更を消して初期状態に戻すときは、対象の KOVA Store ディレクトリで実行します。**保存された演習データはすべて削除されます。**

```sh
docker compose down -v
docker compose up --build -d --wait
```
